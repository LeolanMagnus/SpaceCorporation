# План: механика радара (local radar / gravidar)

> Радар — часть HUD (этап H5 в hud-plan.md), но заводится отдельным планом,
> потому что это механика со своими правилами: кто виден, как часто обновляется,
> как проецируется 3D→2D. Опора на готовое: `NetState` (позиция/скорость у всех
> копий кораблей на клиенте), реестр `NetworkManager.FindShip`,
> `SpatialIndex` (чистая сетка, переиспользуется клиентом), фракции из H4.

## 1. Что такое радар в X4 и что копируем

- Квадратная панель в правом нижнем углу, центр = свой корабль, ориентация —
  курсом «вверх» (radar rotates with the ship, а не мир фиксированный).
- Дистанция охвата: у X4 локальный радар ~несколько км; у нас берём
  **2000 м по умолчанию** (половина сетевого FarRadius 4000 — то, что уже
  доезжает репликой, видно на радаре целиком).
- Маркер = форма по классу (точка/треугольник/ромб/квадрат) + цвет по фракции +
  короткая вертикальная рисочка-«высота» со сдвигом ∝ ΔY (gravidar-оснастка X4).
- Курсовой сектор: контакты показаны относительно носа, стрелки-векторы
  скорости — опционально (переключатель).
- Клик по блипу = выбрать цель (увязка с TargetingService из H3).
- Колесо мыши над радаром / +/- : масштаб 500 / 1000 / 2000 / 4000 м.

## 2. Архитектура: данные отдельно от рисования

### 2.1 Модель контакта (чистая, тестобильная)
`scripts/ui/RadarTypes.cs`, namespace SpaceCorporation.UI:
```
public struct RadarContact {
    public int NetId;            // ShipNetId из NetState
    public Vec3 RelPos;          // позиция относительно своего корабля
    public Vec3 RelVel;          // относительная скорость (для векторов)
    public byte Faction;         // из H4 (0 Neutral / 1 Player / 2 Hostile)
    public byte Shape;           // класс-маркер: ship/target/station
    public bool IsTarget;
    public float Distance;
}
```
`RadarModel` (class, без Godot, как `SpatialIndex`):
- `Update(center, forwardYaw, contacts[])` — фильтр по радиусу и «свежести»,
  поворот в систему координат радара (XZ → 2D, Y → ось высоты), сортировка по
  расстоянию (ближние рисуются поверх дальних);
- гистерезис входа/выхода из радиуса ±10 % (по образцу `SpatialIndex`), чтобы
  блип не мигал на границе;
- кэш прошлого кадра: контакт исчез (корабль удалён/улетел) → блип гаснет за
  0.5 с (fade), а не мгновенно — в X4 цель «теряется» плавно.

### 2.2 Сборщик контактов (Godot-слой)
`scripts/ui/RadarSource.cs`:
- источник — **клиентская** копия мира: обход реестра
  `NetworkManager.RegisteredShips` (добавить `IReadOnlyCollection<Ship>`
  геттер в NetworkManager — реестр уже есть, только не итерируемый снаружи);
- для каждого: `NetState.NetPosition/NetLinearVelocity/FactionValue/ShipTypeValue`
  + `ShipHealthState.Hp` (для состояния «подбит» → маркер мигает); станции
  (`StationState`) — отдельным типом-формой;
- частота сборки **5 Гц** (таймер 0.2 с), не каждый кадр: данных реплики между
  обновлениями всё равно меньше, чем кадров (top Hz < FPS). Между сборами
  `RadarModel` экстраполирует позицию по `RelVel * Δt` (линейно) — блипы
  движутся плавно, по образцу клиентской интерполяции hull;
- свой корабль: `Player.GetMountedShip()` (или `Player` без корабля — тогда
  центр = позиция игрока);
- ориентация радара — **полный локальный базис** своего корабля
  (`forward = −Basis.Z`, `up = Basis.Y`, `right = forward × up`), а не один
  yaw: roll/pitch вращают горизонтальную плоскость — «горизонталь» радара
  (экватор псевдо-3D сферы) остаётся local-горизонталью корабля, объекты при
  крене переезжают между «высотой» и боковыми осями (HeightOffset/ScreenX/Y
  — проекции RelPos на оси базиса).

### 2.3 Виджет
`scripts/ui/RadarPanel.cs : Control` + слот `BottomRight/RadarPanel` в
HudLayer.tscn (размер 220×220, масштабируется темой):
- `_Draw()` — всё векторно: псевдотрёхмерная сфера-каркас (внешний контур
  шара, эллипсы экватора = горизонтальная плоскость корабля, меридианы),
  рамки дальности подписями (1000/2000 м), блипы (по форме), линия проекции
  блипа на плоскость корабля (1 px «штырь» по высоте ΔY — видно
  спереди/сзади/сверху/снизу), векторы скорости, рамка выбранной цели,
  стрелка-«нос» сверху;
- палитра из `HudTheme.FactionColors` (один источник правды с H3/H4);
- текст под панелью: `range: 2000 m | contacts: 7` +
  дистанция цели, если выбрана;
- `MouseFilter = Stop` на панели: клик по блипу →
  `TargetingService.Select(netId)`; колесо → смена масштаба (клампы из списка);
  правый клик по блипу — «держать маркер» (pinned waypoint: стрелка у края
  радара к контакту вне текущего радиуса — как в X4).

## 3. Этапы

### Этап R1 — RModel + юнит-тест (без Godot)
- `RadarTypes.cs`, `RadarModel.cs`; тест `tests/RadarModelTest.cs`:
  фильтр радиуса, гистерезис ±10 %, поворот на курс (контакт «впереди» при
  развороте на 90° уходит вбок), fade исчезнувших, сортировка по дистанции.
- **Критерий:** тест зелёный, чистый код без bpy-подобных зависимостей
  (тестируется так же, как `SpatialIndex`).

### Этап R2 — RadarSource + рисование
- сборщик из реестра, 5 Гц + экстраполяция; `RadarPanel._Draw` с заглушкой
  фракций (все белые, станция — квадрат);
- панель в HudLayer; hot-key `hud_radar` (R? — выбрать неконфликтный,
  F3/Tab/H уже заняты планами) вкл/выкл радар;
- **Критерий (headless, по образцу Stage5):** 2 корабля на сервере на
  дистанциях 300 и 2500 м → у клиента-радара ровно 1 блип в радиусе 2000
  (получаем список из `RadarModel` напрямую, без скриншотов).

### Этап R3 — фракции, интерактив, масштаб
- цвета и формы по `FactionValue`/типу (зависит от H4); клик-выбор цели,
  выделение цели на радаре, pinned-маркер;
- масштаб колесом; затухание исчезнувших;
- **Критерий:** враг в 800 м — красный ромб; клик по нему = выбранная цель в
  H3 (рамка на 3D-модели появилась); цель вне радиуса — стрелка у края.

### Этап R4 (опционально, в перспективе) — радар как МЕХАНИКА
Пока радар = «всё, что доехало репликой, видно всегда». Превращение в игрушку:
- **Дальность радара = свойство корабля/оборудования** (radar range в
  `ShipTypeSpec`), а не глобальная константа: «виден контакт, если
  dist ≤ radarRange и он в AOI-тире». Меньше range — меньше блипов, и
  одновременно (серверная часть) можно резать interest-радиусы по факту:
  сервер уже считает тиры от игрока — range радара ≤ FarRadius обязателен,
  иначе HUD показывает то, чего данных нет;
- **Пассивное/активное сканирование**: активный пинг (клавиша) подсвечивает
  все контакты на 5 с, но «засвечивает» тебя (флаг для будущих боёк/NPC);
- **Невидимость/стелс** крупных дальностей: `NetState`-флаг stealth,
  радар не рисует, пока не ближе X метров (данные всё ещё идут репликой —
  фильтр чисто клиентский + серверный interest; честность держится сервером).
- Каждый подпункт — отдельным шагом, когда будет бой/экономический слой.

## 4. Правила реализации
- Как всегда: состояние рисует только из реплицированных полей
  (`NetState`/`ShipHealthState`/`StationState`), мутаций чужих нет;
- `RadarModel` держим чистой (как `SpatialIndex` в `SpaceCorporation.Net`) —
  юнит-тесты без движка; Godot-обвязка минимальна;
- стоимость кадра: 5 Гц × N контактов, N≈100 → 500 операций — ничтожно;
  `_Draw` только для видимых контактов (после фильтра модели);
- регрессии: тесты в `tests/Stage6Test.*` + headless-прогон, скриншоты не
  нужны — критерии проверяем числами из модели.

## 5. Связки и зависимости
- R3 зависит от H4 (фракции) и H3 (TargetingService) — в hud-plan это
  этапы H4/H3; при параллельной работе R2 стартует независимо;
- реестр `NetworkManager`: нужен итерируемый геттер (маленький PR заранее);
- `Station`: форма-квадрат — `StationState` уже реплицирует позицию
  (`NetPosition` в собственном NetState-подобном узле — уточнить при
  реализации, если NetState у станции отсутствует, добавить форму
  регистрации контактов для станций отдельно).
