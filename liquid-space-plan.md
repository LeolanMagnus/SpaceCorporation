# План: «жидкий космос» + режим пилот-ассиста + скоростные характеристики и модули

Дата: этап 6 (рабочее название — **Stage 6 / Flight Assists & Modules**).
Движок: Godot 4.7.2-stable.mono, C#/.NET 8. Проверка: `./run-tests.sh`.

## 0. Постановка (что просил заказчик)

1. **Космос «жидкий»** — по умолчанию скорость корабля **гасится**: падает со
   временем с тем же ускорением (по величине), с которым набирается.
2. **Режим «отключение поддержки пилотирования»** (`pilot assist`). При
   выключенной поддержке включается **прежнее** поведение: скорость не снижается
   (чистая инерция, `LinearDamping = 0`).
3. **Ускорение — характеристика корабля** (и линейное, и угловое).
4. **Максимальная скорость стрейфа ограничена характеристикой корабля**
   (уже есть потолок угловой скорости `MaxAngularSpeed` — нужен линейный аналог).
5. **Задел под разные скоростные характеристики кораблей с улучшением через
   замену модулей.** Для прототипа достаточно слотов: **РСУ (RCS)**,
   **Маршевый двигатель**, **Радар**, **Батарея конденсаторов**, **Реактор**.

Терминология фиксируем до кода, чтобы код, тесты и панель говорили одними словами:

| Термин | Значение |
|---|---|
| `assist` / Пилот-ассист | Режим «жидкого» торможения: отпустил клавиши → корпус гаснет сам |
| `Coast` | Классическая инерция (ассист выключен) — текущее поведение |
| `ThrustAccel` | Линейное ускорение тяги, м/с² (**не** ньютоны) |
| `DragAccel` | Величина замедления в режиме ассиста, м/с² |
| `MaxLinearSpeed` | Потолок модуля скорости, м/с («макс. скорость стрейфа») |
| `Module` | Слот equip-системы: RCS / Engine / Radar / Capacitor / Reactor |

## 2. Ключевые решения (и почему)

### Р1. Демпфирование заменяем на **кинематическое** (постоянное ускорение), а не экспоненциальное

Заказчик требует буквально: «скорость должна со временем падать **с таким же
ускорением**, как и набираться». Экспоненциальное `v *= exp(-k·dt)` (текущий шаг 6)
этому не соответствует: замедление там пропорционально скорости, а не постоянно, и
«до нуля» он сходится асимптотически. Поэтому в режиме ассиста вводим отдельный чистый
хелпер:

```csharp
/// Кинематическое торможение: |Δv| = dragAccel·dt, строго к нулю (без проскока).
public static Vector3 BrakeToZero(Vector3 v, float dragAccel, float dt)
{
    if (dragAccel <= 0f) return v;
    float len = v.Length();
    if (len <= dragAccel * dt) return Vector3.Zero; // тормозим без проскока через 0
    return v - v * (dragAccel * dt / len);
}
```

⚠ **Торможение ассиста гейтируется отсутствием линейного ввода.** Это критично:
если тормозить постоянно, то при `a_drag == a_thrust` (а по условию они равны!)
тяга и торможение компенсируют друг друга и корабль **не сдвинется вообще**.
Значит формулировка «падает с таким же ускорением, как набирается» — про
**отсутствующий ввод**: торможение действует только когда `Mask & LinearBits == 0`.

Порядок внутри шага (важно для детерминизма):
`тяга (если есть ввод) → торможение (если ввода НЕТ) → демпфирование → потолок`.
Тогда: удерживаемая клавиша — чистый разгон `a_thrust` до потолка; отпущенная —
чистое падение `a_drag = a_thrust` до нуля. Это и есть «жидкость»: корпус тонет
в космосе, но не теряет управление. Тот же гейт, что уже используется в модели для
`f.Axis*` (`Step` читает `f.Mask & LinearBits`, см. FlightModel.cs:170).

Шаг 6 (`LinearDamping`/`AngularDamping`, exp) **остаётся** в модели как отдельная
механика: старые прогоны Stage1/Stage2/Stage5 (тандем с телом, затухание демпфером,
`Docking.SpringC`) считают ровно те же числа. Новое торможение — **над** ним, по
умолчанию `AssistDragAccel = 0` ⇒ структурный ноль = «ничего не изменилось» для
всех существующих тестов. Это та же схема, что уже применена к `MaxAngularSpeed`
(«поле НЕ задаётся в `Default()`, ноль = без ограничения»).

### Р2. Единицы: переходим на **ускорения**, а не силы

`LinearThrust / Mass` — лишнее деление, а масса в прототипе константа. Но ломать
ньютоны = переписать все эталонные числа Stage2Test. Решение: **поле
`ThrustAccel` (м/с²) как источник истины для новой логики**, а `LinearThrust`/`Mass`
остаются и работают как раньше; `ThrustAccel` выводится из них как
`LinearThrust / Mass` и **явно задаётся** из модулей. Т.е.

- `p.ThrustAccel > 0` ⇒ модель берёт ускорение напрямую (путь модулей и ассиста);
- `p.ThrustAccel == 0` ⇒ как сегодня: `LinearThrust / Mass` (старые тесты побитово целы).

Так сохраняется и «задел под улучшение характеристик» (модуль описывает м/с²),
и совместимость. То же для углового: `AngularAccel` (рад/с²) против
`AngularThrust / Mass`.

### Р3. Потолок скорости: один скаляр в прототипе, задел под разные оси

«Максимальная скорость стрейфа» — про стрейф, т.е. про **боковые** оси, у маршевого
двигателя потолок другой. Поэтому в `FlightParams` закладываем **три** числа в
локальной системе корпуса (нос = −Z, конвенция Godot, см. FlightModel.cs:175):

```
MaxSpeedStrafe (локальные X/Y), MaxSpeedForward (−Z), MaxSpeedBack
```

Но **в прототипе реализуем одно поле `MaxLinearSpeed` на все оси**: заказчику нужен
«потолок стрейфа», а different ceilings по осям без геймплея только раздувают
`FlightParams`. Структура задела: при переходе на 3 поля достаточно заменить одно
поле тремя и один вызов `ClampLinear` — формулы выше уже описывают, как это
клиппится (проекция на локальные оси через `Basis.XformInv(v)` / `Xform`, базис
уже есть в шаге: `Basis basis = new Basis(s.Rotation)`).

Направление сохраняем всегда: при превышении режем только те компонент'ы, что
вышли за лимит (не «схлопываем вектор в сферу»), иначе корабль на диагонали начал
бы сам тормозить вдоль разрешённой оси. При одном общем лимите на все оси это
то же самое, что поосевой клиппинг в мировых осях.

Порядок в `Step`: **тяга → торможение ассистом → демпфирование → потолок**.
Потолок — последний, иначе при включённом ассисте (тяга = торможение по модулю)
превышение негде «срезать» и скорость будет дрейфовать вокруг лимита. При
одинаковых `ThrustAccel == AssistDragAccel` удержание клавиши даёт ровно плато
на лимите: a·dt вверх, clip к лимиту, торможение не трогает недобор — и т.д.

### Р4. Состояние ассиста — серверная истина, реплицируется полем в `NetState`

Ассист меняет **физику**, значит менять его обязан авторитет (сервер, id = 1),
иначе предсказание пилота разойдётся с сервером и пойдут реконсиляционные откаты.
Механика ровно как с `DockStateValue`: `[Export] public byte PilotAssist` в
`NetState`, сервер пишет, клиент читает в `StepPrediction` и в шаге предпросмотра
картинки.

**Переключение — не через бит кадра ввода**: `InputFrame` сериализуется в 16 байт
и битов почти не осталось, а состояние ассиста — не «одно нажатие на шаг», а
флаг, живущий долго. Поэтому: `RpcTogglePilotAssist` (как `RpcRequestDock` в
Stage5) с гейтом «отправитель = пилот корабля», сервер меняет `NetState.PilotAssist`
и шлёт реконсиляцию (hard rollback) — у пилота предсказание пересчитывается
с новым флагом. Это дешёвое RPC, не поток данных.

### Р5. Модули = чистая структура данных + сборка `FlightParams`

Никаких узлов и сцен на этот шаг. `Ship` держит `ShipLoadout` (класс/структура),
который из слотов собирает `FlightParams`. Модули — **описания в коде**
(`static class ModuleCatalog`), не `.tres`: для прототипа каталог в C# читаемее
и тестируется без дерева сцены (образец — `Docking`/`CollisionDamage`: чистые
константы и функции, всё проверяется без сцены).

### Р6. Что читается из модулей, а что остаётся константой модели

| Характеристика | Источник (модуль) | Примечание |
|---|---|---|
| `ThrustAccel` (≈ `LinearThrust/Mass`) | Маршевый двигатель | 3 уровня: Mk I / II / III |
| `MaxLinearSpeed` | Маршевый двигатель | потолок стрейфа по всем 6 осям (6DoF = одинаковый лимит по всем) |
| `AssistDragAccel` | Маршевый двигатель (в связке с ассистом) | = `ThrustAccel`: «тормозит так же, как разгоняется» |
| `AngularAccel` (≈ `AngularThrust/Mass`) | РСУ | 3 уровня |
| `MaxAngularSpeed` | РСУ | уже есть в модели (`FlightParams.MaxAngularSpeed`) |
| `RcsOffDragFactor` | РСУ (качество) | множитель демпфирования вращения при выключенном РСУ (для задела; в прототипе = 1) |
| `CapacitorBoost` × `ReactorOutput` | Батарея конденсаторов + Реактор | `BoostMultiplier = 1 + Cap·Reactor`-задел; в прототипе множитель форсажа |
| `PowerBudget` | Реактор | сколько модулей «питается»; при нехватке — режем `ThrustAccel`/`MaxLinearSpeed` множителем `Powered` ∈ [0,1] |
| `RadarRange` | Радар | не входит в `FlightParams`, но хранится в том же `ShipLoadout` — один источник характеристик |

`Mass` остаётся свойством корпуса (`[Export] Mass` на `Ship`), модули меняем не
массу, а **ускорения** — так детерминизм и старые тесты не ломаются, и формула
`ThrustAccel = LinearThrust / Mass` остаётся единственной правдой.

## 3. Реализация по шагам

### Шаг 1 — Модель: флаги ассиста + лимиты (чистый код, без сети)

**Файл:** `scripts/core/FlightModel.cs`

1. В `FlightParams` добавить 4 поля (все с «структурный ноль = прежнее поведение»):
   ```csharp
   /// <summary>Включена ли поддержка пилотирования. 0/false = «космос жидкий-свободный»? НЕТ:
   /// false = ассист ВЫКЛЮЧЕН → инерция сохраняется (текущее поведение).</summary>
   public bool PilotAssist;
   /// <summary>Торможение ассиста, м/с². При PilotAssist=true скорость падает
   /// линейно с этим ускорением (не экспонентой), до нуля без проскока.
   /// 0 = ассист не тормозит (использовать с PilotAssist=false).</summary>
   public float AssistDragAccel;
   /// <summary>Потолок линейной скорости (стрейфа), м/с. 0 = без ограничения.</summary>
   public float MaxLinearSpeed;
   /// <summary>Линейное демпфирование для режима «выключенное РСУ/нет питания»,
   /// 1/с. 0 = нет. Отдельно от AssistDragAccel: это «текучесть», не торможение.</summary>
   public float FreeDriftDamping;
   ```
2. В `Step` — порядок операций (менять только после п.3–6, позиция/ориентация
   интегрируются старыми скоростями, п.1–2 не трогаем):
   ```csharp
   // 5. Скорости: тяга (как сейчас)
   n.LinearVelocity = s.LinearVelocity + worldThrust * dt;
   // 5b. Торможение ассистом — ТОЛЬКО при отсутствии линейного ввода (иначе
   // при a_drag == a_thrust тяга и торможение обнулили бы друг друга, см. Р1):
   // линейное, «равно разгонному», до нуля без проскока.
   if (p.PilotAssist && p.AssistDragAccel > 0f && (f.Mask & InputMask.LinearBits) == 0u)
       n.LinearVelocity = BrakeToZero(n.LinearVelocity, p.AssistDragAccel, dt);
   // 6. Демпфирование экспонентой (старое, трогать не менять!)
   ```
   **Важно:** существующий блок `if (p.LinearDamping > 0f) ... Exp(-k·dt)` оставить
   как есть — на нём висят тесты Stage2Test п.4/п.5 («затухание демпфером»), и
   `Ship._Ready` передаёт туда `LinearDamp = 0`. Новый ассист идёт **отдельной**
   веткой, чтобы не сломать ни один существующий прогон. Поле `FreeDriftDamping`
   в прототипе = 0 и в `Step` не участвует (задел, см. п.1).
3. Добавить `BrakeToZero(Vector3 v, float dragAccel, float dt)` в `FlightModel`
   (сигнатура — см. Р1; чистая функция, тот же стиль, что `ClampLookRadians`).
4. В конце шага (после демпфирования, перед `return`) — потолок линейной скорости
   (осевой клиппинг, см. Р3):
   ```csharp
   if (p.MaxLinearSpeed > 0f)
       n.LinearVelocity = ClampPerAxis(n.LinearVelocity, p.MaxLinearSpeed);
   ```
5. Значения по умолчанию — **в `ShipLoadout` / `Ship._Ready`, не в `FlightParams.Default()`**:
   `Default()` кораблём не вызывается (Ship строит `Flight` сам, Ship.cs:555), и в нём
   `LinearDamping = 0.15f` уже расходится с кораблём (`LinearDamp = 0`). Поэтому
   `Default()` оставляем нетронутым (новые поля = структурный ноль), а базовые
   числа даёт каталог модулей: `ThrustAccel = 90000/1200 = 75 м/с²` (engine Mk I),
   `MaxLinearSpeed = 260` (75 м/с² × ~3.5 с — «разумный» потолок для корпуса
   2×1×4 м в висячей сцене Main), `AssistDragAccel = ThrustAccel` по правилу задачи,
   `AngularAccel = 40000/1200 ≈ 33 рад/с²` (RCS Mk I), `MaxAngularSpeed = 6`
   ([Export] корпуса, уже есть).
6. `ClampLookRadians` уже ограничивает мышь — ничего не добавляем, только
   убеждаемся, что лимит стрейфа не мешает мышью крутить нос.

| 5 | Ассист ВЫКЛ, тяга 1 с, затем пустые кадры 5 с | `|v|` не изменилась побитово = поведение сегодняшнего дня (регрессия Р2) |
| 6 | Торможение ассиста = ускорению набора | время до нуля == время набора до этой скорости (±1 шаг) |
| 7 | Перескок через ноль | при `|v| < a·dt` скорость стала ровно `Vector3.Zero`, не развернулась |
| 8 | Детерминизм | два прогона с одним вводом → побитово одинаково (тот же assert, что п.1 Stage2Test) |
| 9 | Переигровка (`Replay`) с флагом | hard rollback с новым `PilotAssist` даёт ту же историю, что «живой» прогон |
| 10 | Смена флага в середине прогона | состояние после 120 шагов (60 с ассистом + 60 без) ≠ 120 шагов всегда с ассистом — флаг действительно влияет на шаг |
| 11 | `ShipLoadout.Build()` с пустыми слотами | `FlightParams` побитово совпадает с тем, что строит сегодняшний `Ship._Ready` (физика корпусов не уехала) |

| 15 | Деградация по питанию | `Powered < 1` (реактор слабее потребления) → `ThrustAccel` и `MaxLinearSpeed` умножаются на `Powered`, не становясь отрицательными/бесконечными |

### Шаг 3 — Ship: характеристики из loadout'а, а не хардкод

**Файлы:** `scripts/core/Ship.cs`, `scripts/core/FlightModel.cs`, новый
`scripts/core/ShipLoadout.cs`, новый `scripts/core/ModuleCatalog.cs`.

1. `scripts/core/ModuleCatalog.cs` — чистые данные:
   ```csharp
   public enum ModuleKind { Rcs, Engine, Radar, Capacitor, Reactor }
   public readonly struct ModuleSpec {   // name, kind, tier, ThrustAccel, MaxLinearSpeed,
                                         // AngularAccel, MaxAngularSpeed, BoostGain,
                                         // PowerDraw, PowerOutput, RadarRange
   }
   public static class ModuleCatalog { public static ModuleSpec Find(string id); ... }
   ```
   Каталог: `engine_ics_mk1/2/3`, `rcs_ics_mk1/2/3`, `radar_rn-1/2`,
   `cap_c1/2`, `reactor_rt-1/2` — 5 слотов × 2–3 уровня.
2. `scripts/core/ShipLoadout.cs`:
   - `ModuleSpec[5] Slots` (по одному на `ModuleKind`),
   - `bool PilotAssist = true`,
   - `FlightParams Build(FlightParams baseParams)` — собирает ускорения/потолки
     из слотов и накладывает `PilotAssist` + `AssistDragAccel = ThrustAccel`
     (по условию задачи: «с таким же ускорением, как и набиралось»),
   - `Powered = clamp(ReactorOutput / Σ PowerDraw, 0, 1)` — задел под деградацию
     характеристик при нехватке мощности: `ThrustAccel *= Powered`,
     `MaxLinearSpeed *= Powered`.
3. `Ship._Ready`: вместо хардкода `LinearThrust = 90000f` —
   ```csharp
   Flight = Loadout.Build(BaseFlightParams());   // base из [Export]-свойств корпуса
   ```
   `[Export]`-свойства (`Mass`, `MaxAngularSpeed`) остаются: корпус задаёт базу,
   модули — надбавки. `Flight` больше не «свежие числа в `_Ready`», а производная
   от loadout'а → при замене модуля вызывается `RebuildFlight()` и числа
   пересчитываются (для сети — см. шаг 4).
4. Публичный API: `Ship.EquipModule(ModuleKind, string id)` → меняет слот,
   `RebuildFlight()`, печатает в DebugInfoBus новую строку характеристик.
   Для прототипа — только сервер/офлайн (гейт `HasAuthority`, по образцу
   `ApplyImpulseAuthorityOnly`), RPC-обмена инвентарём ещё нет.

**Проверка шага:** `./run-tests.sh` (Stage1Test — свойства корпуса не поменялись)
+ `./run-tests.sh res://tests/LiquidSpaceTest.tscn` (п.11: `Build()` с пустыми
слотами даёт побитово те же `FlightParams`, что сегодня строит `Ship._Ready` →

### Шаг 4 — Сеть: флаг ассиста доезжает до предсказания

**Файлы:** `scripts/core/NetState.cs`, `scripts/core/Ship.cs`.

1. `NetState`: `[Export] public byte PilotAssist { get; set; } = 1;`
   (как `DockStateValue`: `SyncSpawner`-конфиг, `OnChange`, не поток).
2. `Ship`: `bool PilotAssist => Net != null ? Net.PilotAssist != 0 : true;`
   В `StepPrediction` и в серверном шаге — перед `FlightModel.Step` присвоить
   `Flight.PilotAssist = ...; Flight.AssistDragAccel = ...` (один общий путь:
   метод `ApplyAssistToFlight()`, вызывается из обоих шагов, чтобы предсказание
   и истина считали **одинаковые** `FlightParams`; расхождение = детерминизм сломан).
3. `[Rpc] RpcTogglePilotAssist()`: гейт «отправитель = `PilotPeerId`» (копируем
   гейт `RpcRequestDock` / `RpcSubmitInput`), сервер инвертирует флаг в реплике,
   затем реконсиляция пилота (hard rollback: `_hasPrediction = false` → предсказание
   стартует от серверной истины, буфер ввода переигрывается с новым флагом).
4. Клавиша: новое действие `toggle_pilot_assist` в `project.godot [input]`
   (предлагаю **`T`**; `R` уже занят `request_docking`) → `Ship._Input`
   (участок с `toggle_interaction`, `Ship.cs:3138-3159`) → `RpcTogglePilotAssist`.
5. Дебаг: кнопка `DebugInfoBus.RegisterDebugButton("Toggle Pilot Assist", ...)`
   (образец — `Ship.cs:666-678`) + строка в `RegisterInfoSource`:
   `assist = ON|OFF, a_drag = {…}, vmax = {…} m/s`. Без этой строки режим
   отлаживать нечем (тот же аргумент, что в п.35 этапа 5).
6. **Импульсы/столкновения/стыковка** (`ApplyImpulseAuthorityOnly`,
   `_collisionOutVelocity`, пружина `Docking`): лимит стрейфа действует на всё,
   включая импульс от тарана (клиппинг в конце `Step` его накрывает). При
   стыковке (`DockState >= Capturing`) ассист и лимиты не мешают: пружина даёт
   малые скорости (≤ `Docking.DockSpeedLimit = 8`), заведомо ниже потолка — assert п.12.

**Проверка шага:** `LATENCY=100 RUN_SECONDS=14 ./run-net-demo.sh 2` — у пилота
после переключения флага нет «метровой» ошибки: `predErr` в панели возвращается
к ≈0 за ≤1 с. Трафик не растёт (флаг — `OnChange`).

## 6. Что НЕ делается на этом этапе

- Слоты/инвентарь в UI, перетаскивание модулей, магазины, цены, сохранение
  loadout'а между сессиями (RPC-обмен инвентарём вообще).
- Питание как ресурс со временем/разрядкой конденсатора (только `Powered`-множитель).

  один `MaxLinearSpeed` на все оси; структура полей к этому готова.
- Радар как играбельная механика (только `RadarRange` в `ShipLoadout`).
- Угловое «жидкостное» демпфирование при выключенном РСУ (поле `FreeDriftDamping`
  закладываем, в прототипе = 0).
- Ассист стабилизации ориентации (авто-доворот носа к вектору скорости) — только
  гашение линейной скорости.

## 8. Критерии приёмки

**(а) «Космос жидкий»** — при включённом ассисте корабль, отпустивший тягу,
останавливается за `v / AssistDragAccel` секунд, без осцилляций и без проскока
через ноль (п.1/п.6/п.7).

**(б) «Выключенная поддержка = прежнее поведение»** — выключенный ассист даёт
ровно текущую инерцию: `|v|` не меняется после снятия тяги (п.5), поведение
сегодняшних сцен не изменилось (прогоны стадий 1/2/5 целы).

**(в) «Потолок стрейфа»** — ни одна ось не превышает `MaxLinearSpeed` ни при
каком вводе, включая диагонали, форсаж и импульсы (п.3/п.4); потолок — из
характеристик корабля и меняется с модулями (п.11/п.14).

**(г) «Задел под характеристики и улучшение модулями»** — все скоростные
характеристики собираются из `ShipLoadout` в одном месте; замена Mk I на Mk II
меняет `ThrustAccel`/`MaxLinearSpeed`/`AngularAccel` предсказуемо, без правки
`Ship.cs` (п.11–п.14).

**(д) «Сеть не поехала»** — флаг ассиста реплицируется, у пилота нет ложных
откатов после его переключения, трафик не вырос (демо-замер + п.13).
