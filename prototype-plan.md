план разработки прототипа (Godot 4 + .NET)
1. Техническая основа и архитектура
Движок: Godot 4.x (Mono/.NET). Гравитация отключается глобально (Physics/3D/Default Gravity = 0), для персонажа на магнитных ботинках имитируется «магнитным притяжением» к поверхности.

Ключевой принцип: корабль — RigidBody3D с gravity_scale = 0; персонаж — CharacterBody3D (проще контролировать выравнивание по поверхности). «Мягкая» стыковка — Joint3D или ручная пружина в _IntegrateForces().

Структура сцены:

Station — StaticBody3D + CylinderMesh, DockingPoint, платформа, огни.

PlayerShip — RigidBody3D + ShipController.cs + ShipHealth.cs + LaserWeapon.cs.

PlayerCharacter — CharacterBody3D + MagneticBootsController.cs.

DebugLayer — CanvasLayer с кнопкой «Debug Mode» и растущей панелью кнопок.

Слои коллизий: Ship, Station, Character, Target. RayCast3D для стрельбы и ботинок исключает ненужные слои.

2. Этапы (в порядке приоритета)
Этап 1. Фундамент + оболочка дебаг-режима (0.5 недели)
Цель: пустая сцена, в которой уже есть тестовый стенд для всего остального. Делается первым — иначе тестировать нечем.

Задачи:

Создать Godot-проект, слои коллизий, отключить глобальную гравитацию.

DebugLayer (CanvasLayer):

Button в левом верхнем углу, зелёный текст, надпись «Debug Mode», изначально Visible = false.

F3 — toggle видимости кнопки.

Клик по кнопке — показать/скрыть PanelContainer с VBoxContainer.

Внутри панели — пока только Label «Debug Info» (пустой) и заготовка метода RegisterDebugButton(string label, Action callback), чтобы кнопки добавлялись одной строкой по мере появления механик.

Заготовка DebugInfo-апдейтера в _Process: сюда потом будут писаться скорость корабля, угловая скорость, HP, состояние стыковки.

Критерий готовности: F3 → кнопка → панель открывается; RegisterDebugButton работает (тестовая кнопка печатает в консоль).

Смысл этапа: к концу недели 1 у тебя есть «приборная панель» для отладки всех последующих механик. Дальше в каждом этапе ты просто добавляешь в неё 1–2 кнопки.

Этап 2. Пилотирование корабля 6DoF (1 неделя)
Цель: корабль летает и вращается строго по заданной схеме.

Задачи:

ShipController на RigidBody3D: gravity_scale = 0, linear_damp ≈ 0, angular_damp ≈ 1.5.

6DoF-управление в _PhysicsProcess:

A/D — стрейф по Basis.X.

Ctrl/Space — вертикаль по Basis.Y.

W/S — продольная тяга по Basis.Z.

Z/X — множитель общей тяги.

Q/E — ApplyTorque() вокруг Basis.Z с максимальной угловой скоростью.

Мышь: ось X — yaw, ось Y — pitch. Корабль доворачивает к курсору с ограничением MaxAngularSpeed (Basis.Slerp / Quaternion.RotateTowards-логика).

В дебаг-панель добавить: Label с текущей скоростью, угловой скоростью, текущим уровнем тяги.

Критерий готовности: инерция сохраняется, вращение читается, при перевороте управление не инвертируется.

Этап 3. Стрельба хитсканом + мишени (0.75 недели)
Цель: лазер мгновенно попадает в точку под курсором и рисует луч. Мишени — визуальные референсы в пустоте и валидатор корректности осей корабля.

Задачи:

Хитскан: из Muzzle (Node3D в носу) — PhysicsDirectSpaceState3D.IntersectRay в направлении точки под курсором.

Сначала получить точку под курсором (raycast из Camera3D), затем направить луч из Muzzle в эту точку — так выстрел визуально идёт из носа, а не из камеры.

Визуал луча: MeshInstance3D с ImmediateMesh (две вершины), белый StandardMaterial3D без освещения. Включить на 0.2 сек, затем скрыть (корутина / Timer).

Мишени: кнопка Spawn Target в дебаг-панели создаёт перед кораблём StaticBody3D + BoxMesh + TargetHealth (HP = 100). Над кубом — Label3D (HP) + Sprite3D/TextureProgressBar (healthbar). Кнопка Clear Targets — удалить все (по группе targets).

В дебаг-панель добавить: Spawn Target, Clear Targets.

Критерий готовности: ЛКМ → белая полоса на 0.2 с → у мишени падает HP и хелсбар. Стрельба попадает в точку под курсором, а не «примерно туда».

Почему до станции: если лазер летит не туда — значит, Basis корабля собран неверно, и это надо поймать до того, как поверх него начнёшь навешивать стыковку. Плюс мишени дают визуальные точки в пустоте, без них тестировать пилотирование неудобно.

Этап 4. Станция + урон от столкновений (1 неделя)
Цель: есть статичный объект, в который можно врезаться и об который можно убиться. Станция пока без логики стыковки — только геометрия, огни (выключены) и DockingPoint.

Задачи:

Станция: StaticBody3D + CylinderShape3D + CylinderMesh; платформа + DockingPoint (Node3D); 4–8 OmniLight3D/SpotLight3D (или emissive-материалы), изначально Visible = false.

Урон от столкновений (ShipHealth):

В Godot нет Collision.impulse как в Unity. Два подхода:

Проще: сигнал RigidBody3D.BodyEntered — вычислить относительную скорость LinearVelocity - other.LinearVelocity (для RigidBody3D) и оценить импульс как relativeSpeed * Mass.
Точнее: _IntegrateForces() с PhysicsDirectBodyState3D — пройтись по контактам (ContactCount, GetContactImpulse(i)).
Damage = impulse * DamageCoefficient, с порогом MinImpulseThreshold (защита от микроколлизий и трения).

В дебаг-панель добавить: Toggle God Mode (корабль не получает урон), Show HP в debug-info.

Критерий готовности: таран станции на высокой скорости снимает ХП; медленное касание — нет.

Почему до стыковки: станция как статичный коллайдер нужна и для тарана, и для стыковки. Урон от столкновений — простая механика, тестируется за 30 секунд, и логично закрыть её до того, как на станцию навешивается сложная логика захвата.

Этап 5. Стыковка (1 неделя)
Цель: полный цикл «радиосвязь → огни → захват → посадка».

Задачи:

Радиосвязь: Area3D (DockingZone) вокруг станции. В зоне игрок жмёт F → RequestDocking(). Если скорость ниже порога — включить огни, состояние DockingApproved.

Мягкая стыковка:

Area3D радиусом 1.5–2 м у DockingPoint — вход в DockingCapture.

Корабль не телепортируется. Два варианта:

Joint3D: Generic6DOFJoint3D с ограничениями и демпфированием между кораблём и станцией.
Ручная пружина в _IntegrateForces(): Force = (targetPos - shipPos) * k - linearVelocity * d, плюс гашение angularVelocity, с ограничением максимальной силы.
Через 1–2 сек — фиксация (Freeze = true) в позиции DockingPoint.

В дебаг-панель добавить: Teleport to Docking Zone — критично для итерации стыковки (без неё каждая проверка = минута полёта, с ней = секунда), State: [DockingState] в debug-info.

Критерий готовности: огни загораются до захвата; корабль «подхватывается» без рывков; после фиксации не дрейфует.

Этап 6. Персонаж + магнитные ботинки (2 недели — самый рискованный этап)
Цель: игрок выходит в невесомость, ходит по станции, отключает ботинки и улетает.

Задачи:

Переход: при стыковке активируется PlayerCharacter (Visible = true, SetPhysicsProcess(true)), камера (Camera3D.Current = true) переключается. Корабль остаётся на месте.

Контроллер персонажа (CharacterBody3D):

MotionMode = Floating, перемещение — Velocity в локальных осях, только когда ботинки включены и есть контакт с поверхностью.

Магнитные ботинки (включены):

RayCast3D (или 3–4 для устойчивости на цилиндре) вниз. При попадании в Station в пределах 1.2 м — выравнивание Basis.Y по нормали (Basis = Basis.Orthonormalized()).

«Магнитное притяжение» — небольшая скорость вниз по нормали (Velocity += -Normal * MagneticPull * delta).

Движение — вдоль касательной плоскости (input - normal * input.Dot(normal)).

Вертикальное перемещение заблокировано, пока ботинки активны.

Отключение ботинок (B):

Снимается ограничение по вертикали, персонаж сохраняет скорость и может оттолкнуться (Velocity += LookDirection * JumpForce).

В полёте Velocity не гасится — летит с постоянной скоростью, пока не включит ботинки у поверхности или не столкнётся.

В дебаг-панель добавить: Toggle Boots (принудительно), Teleport to Platform (для быстрой проверки ходьбы без стыковки).

Критерий готовности: персонаж ходит по цилиндру и платформе без «дрожи»; при отключении ботинок и прыжке улетает по инерции; при включении у поверхности — прилипает и выравнивается.

Этап 7. Интеграция + полировка (1 неделя)
Задачи:

Связать все системы в единый цикл: «заспавнился → подлетел → запросил стыковку → сел → вышел → прошёлся → отключил ботинки → улетел → вернулся → выстрелил в мишень».

Настройка «ощущения»: демпфирование вращения корабля, k/d пружины стыковки, скорость магнитного притяжения, сила отталкивания от станции.

Финальная проверка дебаг-кнопок (все ли работают, все ли нужны).

Критерий готовности: билд проходится по сценарию без багов, «ощущение» полёта и стыковки субъективно читается.

4. Риски (с учётом специфики Godot) — без изменений по сути, но с новым порядком смягчения
Риск	Почему опасен в Godot	Смягчение
Магнитные ботинки «дрожат» на цилиндре	CharacterBody3D.MoveAndSlide() даёт несколько коллизий за кадр	Усреднять нормали нескольких RayCast3D с Basis.Slerp, не менять GlobalTransform напрямую каждый кадр
Стыковка «дёргается»	Joint3D нестабилен на высоких скоростях	Ограничить скорость входа в зону; Generic6DOFJoint3D с демпфированием или ручная пружина с maxForce
Нет Collision.impulse	Импульс контакта не отдаётся так же просто, как в Unity	Относительная скорость × масса (этап 4) как приближение; _IntegrateForces + GetContactImpulse для точности
Стрельба не туда	RayCast3D из Muzzle и луч камеры — разные	Сначала hit.point из камеры, затем луч из Muzzle в эту точку; если не достаёт — стрелять в направлении hit.point
Дебаг-меню конфликтует с вводом	F3 может пересекаться с игровыми действиями	При открытом меню GetTree().Paused = true (ProcessMode = Always у CanvasLayer)
Локальные силы применяются неверно	Глобальные оси инвертируют управление при перевороте	Всегда умножать силу/торк на GlobalTransform.Basis.X/Y/Z
5. Минимальный набор ассетов
Корабль: BoxMesh/CapsuleMesh/CylinderMesh + CollisionShape3D.

Станция: CylinderMesh + BoxMesh-платформа + OmniLight3D/SpotLight3D (или emissive).

Персонаж: CapsuleMesh + Camera3D (первое лицо).

Лазер: MeshInstance3D + ImmediateMesh, белый StandardMaterial3D без освещения.

UI: CanvasLayer + Button + Label + TextureProgressBar для хелсбара.
