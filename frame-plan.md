# План промежуточной стадии: локальные системы отсчёта («захват» объектов)

Дата: 2026-08. Стадия: промежуточная (без полного локального кадра и без ротационного
переноса позы). Родственные планы: `net-refactor-plan.md` (снапшоты), `stage5-plan.md`
(стыковочная пружина), `eva-plan.md` (свободный полёт игрока), `radar-plan.md`.

## 1. Механика

Объект A (корабль, игрок) считается **захваченным** объектом B (корабль большей массы /
позже — станция), если A находится «вблизи» B. Пока захват активен:

- движение A считается **в системе отсчёта B**: глобальная скорость A =
  скорость кадра B в точке A + относительная (локальная) скорость A;
- тяга, ограничение скорости и сопротивление A работают по **локальной** скорости —
  «внутри пузыря» маленький корабль летает относительно большого, как в кабине;
- B, двигаясь, **переносит** A с собой (A летит вместе с B, если сам не двигателями);
- HUD показывает **локальную скорость синим жирным** рядом с обычной глобальной.

Примеры: курьер внутри контейнеровоза; игрок (EVA-план) рядом с пролетающим кораблём —
захватывается и движется вместе с ним; малый корабль внутри большого флагмана.

## 3. Ключевое проектное решение: кадры через ПОЛЕ СКОРОСТЕЙ, а не через локальные координаты

Полная реализация «локальных координат» — хранить позу A относительно B
(`pos_A = pos_B + basis_B · local`, снапшотить `local`) — трогает формат пакетов,
интерполяцию вращающегося родителя, радар, докинг, бортовые журналы. Это стадия «после».

**Промежуточная стадия** использует эквивалент для кинематики твёрдого тела:
скорость кадра B в мировой точке P:

```
v_frame(P) = v_B + ω_B × (P − pos_B)
```

(на этой стадии ω-член выключён константой `FrameRotational = false`.)

- Истина прежняя: глобальные `GlobalPosition` / `LinearVelocity` каждого корабля;
  снапшоты, `ShipRecordCodec`, дельта-энкодеры, Replay, радар, докинг — **без изменений формата**.
- Захваченный A интегрируется так: `v_A = v_frame(pos_A) + v_rel`, где тяга,
  ограничения и демпфирование в `FlightStep` применяют к `v_rel`, а не к `v_A`.
- Локальная скорость для HUD: `|v_rel| = |v_A − v_frame(pos_A)|`.
- Интерполяция вращающегося родителя не нужна: клиент интерполирует A и B как раньше
  (глобально), а `v_rel` вычисляет из уже интерполированных поз и скоростей.
- Детерминизм: `FlightStep` остаётся чистой функцией; правило захвата — чистая функция
  состояний (§4); Replay и тесты-сценарии не ломаются.

Честное ограничение: `v_rel` — производная величина, в пакетах её нет. При рассинхроне
поз ошибка `v_rel` равна сумме ошибок поз и скоростей A и B (после фильтра — десятки
см/с, для HUD до 1 м/с). Это приемлемо: локальная скорость — отображение и геймплейный
лимит, а не сетевое состояние.

## 4. Правило захвата (сервер-авторитет, чистая функция)

Новый файл `scripts/core/CaptureRules.cs`, без Godot-типов (тестируется через `dotnet run`):

```csharp
public static bool TryCapture(
    float massA, VectorLike posA, VectorLike vA, float radiusA, int idA,
    float massB, VectorLike posB, VectorLike vB, float radiusB, int idB,
    bool parentDocked, bool parentCaptured, CaptureTuning t) => ...
```

Пороги в `CaptureTuning` (одна таблица, как `Docking.Tuning`):

- `RatioMin = 3f` — масса B ≥ 3 × массы A (1200 vs 5200 = 4.3, 5200 vs 10000 = 1.9 →
  хавлер курьер захватывает, контейнеровоз хавлер на этой стадии — **нет**, если
  не опустить порог до 2: это настройка баланса, не механики);
- `Radius = max(radiusB, radiusA) + CaptureMargin` (margin 25 м; radius ≈ половина
  диагонали hullSize: Courier ~2.4 м, Hauler ~9.2 м, Freighter ~11 м);
- `VAttachMax = 25 м/с` — по |v_rel| при входе: быстро пролетевший мимо объект
  захвачен быть не должен;
- **гистерезис**: порог выхода = порог входа × 1.4 (по расстоянию и по скорости) —
  иначе на границе объект «мигает» захватом и его траектория дрожит;
- выход: `|posA − posB| > ReleaseRadius` или родитель уничтожен/вышел из реестра
  (`ShipNetRegistry`) или `parent.IsDocked` (села на станцию → пузырь гаснет;
  снятие со станции не даёт авто-захват — только при следующем соблюдении входов).

Правила порядка (детерминизм и предсказуемость):

- **один** родитель: наибольший по массе из подходящих (при равенстве — меньший netId);
- **запрет вложенности**: захваченный объект не может сам быть родителем — A,
  захваченный B, не может захватить C; цепочка глубины 1. Снимает половину рисков
  экстраполяции;
- проверка каждые N физ. шагов (N = 4, ≈4 Гц), решение с гистерезисом;
- захват/расхват логируется в `DebugInfoBus` (`capture: ship#7 ← #12`) — видно в F9.

Интеграция в `AdvanceFlight` (`Ship.cs:1530` — общая точка для `_IntegrateForces`,
`StepPrediction`, откатов и тестов; правило захвата считает только авторитет):

1. до `FlightModel.Step`: если `CaptureParentNetId > 0`, тяга и ограничения считаются
   в кадре: `v_in = v_A − v_frame(pos_A)`; `v_out = Step(..., v_in, ...)`;
   затем `v_A' = v_frame(pos_A) + v_out`;
2. интегрирование позиции (внутри `FlightModel.Step`) идёт глобальной `v_A'` —
   перенос родителем происходит «сам собой», потому что `v_A'` содержит `v_frame`;
3. `MaxLinearSpeed` ограничивает **`v_rel`**, а не `v_A`: «внутри пузыря» спидометр
   именно локальный, глобальная скорость может превышать лимит (летим на буксире) —
   это и есть желаемый эффект;
4. `TestStepForTest` обязан идти тем же путём, иначе автотесты разойдутся с боевым шагом;
5. коллизии: на время захвата `AddCollisionException` (родитель ↔ захваченный) и
   снятие при расхвате, иначе корпус родителя выталкивает захваченного.

## 5. Захват игрока (пересекается с `eva-plan.md`)

Игрок — `CharacterBody3D` в мировом корне, движение: `Velocity = wish * speed;
MoveAndSlide()` (`scripts/core/Player.cs:312`). Захват игрока — НЕ репанторинг к
`AttachPoint` (это «сидеть в кресле», кнопка F именно его снимает), а **аддитивная
добавка скорости кадра**:

```
Velocity = wish_local * speed + v_frame(GlobalPosition)
MoveAndSlide();
```

- «вперёд» для WASD берётся из базиса родителя — тот же приём, что
  `MoveInAttachedPlane` (`Player.cs:304`), но узел остаётся в мировом дереве:
  маска `Station | Target` и коллизии не ломаются;
- `wish_local * speed` = локальная скорость, она же идёт в синий HUD;
- критерии те же, что `CaptureRules`: масса игрока `PlayerMass = 100 кг`, любой
  корабль превосходит её в ≥12 раз, радиус — по габариту корабля;
- `MoveAndSlide()` двигает глобально, поэтому перенос родителем идёт через член
  `v_frame`; при рассхвате игрок сохраняет глобальную скорость (кадр не «гасится»);
- порядок с `eva-plan.md`: EVA вводит сбор ввода свободного полёта (`wish`, рывки,
  кислород). Захват надстраивается **над** этим как один аддитивный член — сначала
  EVA, потом захват, иначе оба правят одну строку `Velocity = ...`.

## 6. Реализуемо ли в сетевой модели: да, с одной крупной оговоркой (предсказание)

Что НЕ меняется:

- формат пакетов (`ShipRecordCodec`: 21/25/14 Б, int16-смещение от якоря, кватернион
  с пропуском макс. компоненты, скорости int10/int8) — истиной остаются **глобальные**
  позы и скорости, локальная скорость выводится каждым пиром сама;
- якорь тира (`FlagHasAnchor`), дельта-тик, тиры near/mid/far, дельта-энкодеры;
- канал ввода: кадр ввода — силы/кнопки (`InputMask`-биты на 1 физ. шаг), сервер
  исполняет их из `_serverQueue`; захват меняет только **шаг симуляции**;
- Replay / бортовые журналы пишут глобальные состояния — захват восстановим из них,
  правило детерминировано.

### 6.1 Флаг захвата — только от авторитета

`v_rel` каждый пир выводит сам из поз A и B, но **сам факт захвата** обязан прийти
от авторитета: момент входа/выхода определяет, применялся ли `v_frame` в шагах
`v_A`, и расхождение по тикам даёт ошибку поз порядка `|v_frame| · Δt_перехода`.
Поэтому захват — **событийная фаза по образцу докинга и ассиста**:

- в `NetState` добавляется `CaptureParentNetId` (int, по образцу
  `DockStationNetId`, `NetState.cs:56`) + `CaptureTick` — **сим-тик, с которого
  фаза действует**;
- переходы шлются тем же путём, что `SetDockPhase` (`NetworkManager.cs:393`) и
  смена флага ассиста (`RpcTogglePilotAssist`, `Ship.cs:800`) — событийный RPC,
  который обязан прийти раньше ненадёжных кадров (тот же порядок, что у
  док-фазы и ассиста: сервер меняет поле `NetState`, реплика реагирует через
  `OnChange`);
- источник истины — авторитет: он считает `CaptureRules` раз в 4 шага и рассылает
  переходы; клиент только применяет их.

### 6.2 Оговорка: у корабля-пилота ЕСТЬ предсказание с откатом — его это задевает

В коде уже есть полноценный rollback: кольцо `_pending` (256 кадров, :497),
клиентская переигровка `ReplayInputsAfter` (:3507), серверная `ReplayAllApplied`
(:805) и `ReconcileWith` (:3385) с порогом `ReconcileThreshold = 0.3f` м (:493). Захват входит в `StepPrediction`, значит
переигрываемые кадры должны знать, был ли корабль захвачен **на том тике**, и
нужен `v_frame` родителя на том же тике — полной истории родителя в предсказании
нет. Это же уже проходили с флагом ассиста: сервер переигрывает историю целиком
(`ReplayAllApplied`), а клиент глушит реконсили на `AssistMuteFrames` кадров.

**Промежуточное решение (дешёвое и уже проверенное в этом коде)**: на фазе
захвата пилот-клиент ведёт себя как на dock-фазе — **не предсказывает и не
реконсирует**, позу ведёт сервер, картинка идёт через `InterpolateHull`
(готовый гейт `_clientDockPhaseActive`, `Ship.cs:3058` и :3190: при
`DockState >= Capturing` предсказание выключается, тело едет за картинкой).
Переход в захват и из него — разрыв, на котором допустим один жёсткий снап к
серверному снимку. Цена: управление внутри пузыря с RTT-задержкой ввода — для
промежуточной стадии приемлемо (внутри пузыря основной сценарий — «везёт»,
тонкая манёвренность потом).

Отказ от предсказания на фазе захвата снимает риски раскатки полностью; полный
вариант (пер-тик состояние захвата в кольце + история позы родителя из
интерп-буфера по `SimTick`) — следующая стадия.

### 6.3 Наблюдатель: отставание реплики от родителя

`InterpolateHull` (:3535) **не экстраполирует** — кадр позже свежего снимка рисуется
по свежему. Захват A родителем B означает: поза A на 100% «едет» на v_frame, а
снимки A приходят с задержкой `_interpDelay` и квантом 1 см → видимое отставание A
от B до `|v_frame| · interpDelay` (при 100 м/с и 0.1 с — 10 м, слишком много).
Правка на этой стадии: при `CaptureParentNetId > 0` точка интерполяции A
**смещается вдоль `v_frame(A)` на `interpDelay`** (сдвиг точки съёмки, без новой
экстраполяции) либо интерполируется **пара** (A относительно B: `posA = posB + Δ`,
где Δ интерполируется по истории относительных поз из снимков — оба в near-тире
рядом и синхронно). Второй вариант точнее и делает картинку «внутри пузыря»
жёсткой; это и есть настоящая «локальная система отсчёта» на визуальном уровне —
реализуема на существующем транспорте, формат пакетов не меняется.

Оговорка: у **дальнего тира** (`FarRecordSize` = 14 Б) скоростей нет — захват
дальше тира near/mid не считается, в far показываем только позу без уноса.

| R7 | Квант скорости 0.1 м/с и позиции 1 см: `v_rel` — разность близких величин | на малых локальных скоростях шум ±0.2 м/с, HUD мигает | вывод до 1 знака; сглаживание `v_rel` (фильтр τ = 0.3 с) **только для HUD**, физику не трогать |

| R9 | `CharacterBody3D` + `MoveAndSlide`: унос «съедается» скольжением по нормали станции | локальная скорость игрока врёт при контакте | брать `v_rel` из `GetRealLinearVelocity()` после `MoveAndSlide`, а не из `wish` |
| R10 | Порог «превосходящей массы» зависит от `Flight.Mass`, которая меняется модулями/грузом | захват «прыгает» при перегрузке | гистерезис и по массе: вход при ratio ≥ 3, выход при ratio < 2 |

## 8. План работ (шаги; каждый — проверяемый инкремент)

Порядок: сначала чистые функции и тесты, затем интеграция, затем сеть, затем HUD.

1. **`scripts/core/CaptureRules.cs`** (чистый C#, без Godot) — `TryCapture` +
   `CaptureDecision`; пороги в `CaptureTuning`: `RatioMin = 3`, `RatioRelease = 2`,
   `VAttachMax = 25 м/с`, `Hysteresis = 1.4`, `CheckEveryN = 4`; радиус от габарита
   родителя. Вход — значения, не узлы: `(massA, posA, vA, massB, posB, vB, radiusB,
   parentIsDocked, parentIsCaptured)`.
2. **Тесты** в `tests/` по образцу существующих чистых тестов (`dotnet run`): вход /
   выход, гистерезис по радиусу и по массе, «влетел слишком быстро — не захват»,
   «родитель на станции — пузырь гаснет», запрет вложенности, выбор наибольшего.
3. **`Ship.cs`**: поля `CaptureParentNetId` / `IsCaptured` + `CaptureTick`; метод
   `FrameVelocityAt(pos)`; шаг в кадре — **внутри `AdvanceFlight` (:1530)**, чтобы
   `_IntegrateForces`, `StepPrediction`, откат `ReplayInputsAfter` и
   `TestStepForTest` шли одним путём; отчёт пар в `DebugInfoBus`
   (`RegisterInfoSource("Ship", ...)`).
4. **Тест-сценарий «малый внутри большого»**: большой летит `+X` на 100 м/с, малый
   держит `v_rel = 0` → расстояние между ними постоянно (сейчас растёт). Это и есть
   критерий всей стадии.
5. **Коллизии**: `AddCollisionException` / `RemoveCollisionException` в переходах
   захвата (новый слой не обязателен, биты 9..20 свободны — оставить про запас).
6. **Сеть**: поля `CaptureParentNetId` + `CaptureTick` в `NetState` (:56, по образцу

   сдвиг интерполяции вдоль `v_frame` или интерполяция пары A↔B (§6.3);
   гейт «захват только в тире near/mid». Формат `ShipRecordCodec` не трогаем,
   тесты кодека не меняются.
7. **HUD**: `scripts/ui/HudLayer.cs:291-297` (`_lblSpeed`, строка вида

   Color(0.35f, 0.7f, 1f))` + `AddThemeFontVariationOverride("font_weight",

9. **Radar**: семантику не менять (глобальная поза и относительная к наблюдателю
   скорость), но в легенде помечать источник с `CaptureParentNetId > 0`.
10. **Отладка**: строка в панели F9 `cap: #7→#12 v_rel=(…)`; проба
    `tests/probes/ProbeCaptureFrame.cs` по образцу `ProbeStationPen.cs` — проверить,
    что `AddCollisionException`, вызванный из `_IntegrateForces`, реально действует
    в этом же физическом шаге (проблема из шага 4.7: примитивов penetrate в
    C#-биндинге нет, а пространство во время шага доступно).

### Что явно вне промежуточной стадии

- локальные координаты в пакетах (`pos_A` относительно B) и ротационный перенос позы;
- «внутрибортный» режим: палубы, шлюзы, физика внутри корпуса — это стадия 6 / EVA;
- гравитация и ИИ-навигация внутри чужого кадра;
- захват станцией (станция сейчас статична, её масса «∞» тривиальна);
- вложенные цепочки глубины > 1;
- вращательный член `ω × r` (включается отдельной стадией с лимитами).
