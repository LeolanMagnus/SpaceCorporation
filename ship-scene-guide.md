# Инструкция дизайнеру: сцена корабля, которая свободно интегрируется в игру

Все пути — от корня проекта Godot (`scenes/`, `scripts/`, `assets/`).
Эталон, с которого всё копируется: **`scenes/Ship.tscn`** (курьер). Не изобретайте
свою структуру — копируйте эталон и меняйте только помеченное ниже.

## 0. Главные правила (нарушение = рассинхрон физики и картинки)

1. **Ось −Z = нос корабля.** Вся логика полёта (тяга, прицел турели, посадка)
   считает носом −Z. Разверните модель в Blender на 180°, если нос смотрит на +Z.
2. **Один метр Blender = один метр игры.** Модель должна вписываться в габарит
   коллайдера 1:1 (см. п.2). Не масштабируйте модель в сцене — правьте в Blender.
3. **Физика — всегда один бокс, картинка никогда не участвует в коллизии.**
   Не делайте составной коллайдер по форме корпуса и не вешайте коллайдеры на
   модель. Игрок «входит» в выступы картинки — это норма (слой корабля для
   персонажа только в лучах, не в коллизиях).
4. **В сцене корабля НЕ должно быть узла `Player`.** Игрок спавнится отдельно
   (`WorldSpawner`); инстанс игрока внутри корабля при спавне ломает ему
   гравитацию/прилипание и ломает тесты.
5. **Ничего лишнего в дереве.** Каждый узел в сцене читается кодом или тестами.
   Пустые «для красоты» узлы, случайные `MeshInstance3D` вне `ShipHull`,
   замеченные в редакторе правки трансформов корня — частая причина странных
   багов. Правило: сделали правку — прогоните тесты (п.8).

## 1. Модель в Blender (то, что потом ляжет в `assets/models/`)

Требования к GLB (`assets/models/<тип>.glb`):

- **Manifold** (закрытая сеть, без дыр/сдвоенных граней), нормали наружу.
  Проверка в Blender: Select All → Mesh › Normals › Recalculate, и
  3D-Print Toolbox › Check.
- **Фаски/скругления** допустимы, но габариты итогового силуэта — ровно
  коллайдер (п.2). Пример курьера: корпус 2×1×4 м, нос −Z.
- **Ориджин модели — в центре габарита** (центр массы бокса), пол каюты при
  этом на `y_local = -0.4` от центра (как палуба `DeckInterior` в эталоне).
- **Одна сетка или несколько — можно**, но единым GLB; материалы простые
  PBR (glTF-совместимые), без процедурных нод.
- **Экспорт:** File › Export › glTF 2.0, *Y Up* (Godot сам конвертирует),
  Apply Modifiers on, без анимаций/камер/света.
- После добавления GLB в `assets/models/` Godot импортирует сам
  (появится `<имя>.glb.import`). UID импортированного файла пригодится для
  `ext_resource` в сцене.

## 2. Габарит и каталог типов (`scripts/entities/ShipTypes.cs`)

Габарит корабля живёт в **каталоге** `ShipTypeSpec.HullSize` (ширина, высота,
длина, м), и он же задаёт размер коллайдера (`CollisionShape3D`), массу
(`RigidBody3D.Mass`) и параметры полёта (`Base = new FlightParams { ... }`).

- Модель подгоняется под `HullSize`, а не наоборот.
- Новый тип корабля = новый `ShipTypeSpec` в каталоге + новый член enum
  `ShipType` + инстанс-сцена (п.4). Менять существующие цифры можно только
  вместе с тестами (они сверяют массу/тягу/габарит с каталогом).
- Цветовая заглушка `HullColor` и навесы `Accessories` — наследие примитивной
  картинки; для кораблей с art-моделью они не участвуют в интеграции
  (навесы `HullAccessories` генерируются кодом только как временный силуэт).

## 3. Скелет сцены (что обязан содержать любой корабль)

Корень — `RigidBody3D` со скриптом `scripts/entities/Ship.cs`.
Обязательные дети (имена — контракт, код ищет их по имени):

| Узел | Тип | Зачем | На что смотреть дизайнеру |
|---|---|---|---|
| `CollisionShape3D` | `CollisionShape3D` (Box) | Физика корпуса. Слой 1, маска 3 (Station\|Target) | Размер пишет код из каталога; в сцене — эталонный бокс курьера. Для нового типа — бокс новых габаритов |
| `ShipHull/` | `Node3D` | Оболочка картинки | Только визуально-нефизические дети |
| `ShipHull/<Model>` | инстанс GLB | Art-модель | `visible = false` в сцене; код сам включает для своего типа (`Ship.cs`, блок про `CourierModel`) |
| `ShipHull/AttachPoints/Seat` | инстанс `scenes/Seat.tscn` | Кресло пилота | `IsDefaultForPlayer = true`, `PlayerOffset` — куда садится игрок; позиция — там, где реально стоит кресло в каюте |
| `ControlPanel` | инстанс `scenes/ControlPanel.tscn` | Панель «F — сесть за штурвал» | Слой 512 (`ControlPanel`), маска 0; `SeatPath` → на `Seat`. Область ~0.45 м куб у кресла |
| `Decks/DeckHull` | `StaticBody3D` | Палуба корпуса (по ней ходят ботинки) | Слой 256 (`Deck`), маска 0; бокс = габарит корпуса |
| `Decks/DeckInterior` | `StaticBody3D` | Пол каюты, чуть ниже центра | Слой 256; верх грани = уровень пола, по которому ходит игрок |
| `Decks/CabinWalls/...` | `StaticBody3D` | Стены каюты (герметичный объём) | Слой 256. Стены обязательны: hover-панель и кресло должны быть внутри каюты, снаружи они перекрыты стеной — это фича, не баг |
| `Decks/Airlock` | инстанс `scenes/Airlock.tscn` | Шлюз для входа снаружи (двери внутри — инстансы `scenes/Door.tscn`) | Ставится в кормовой/бортовой проём; внутренняя дверь — в каюту, внешняя — наружу |
| `Weapon` | инстанс `scenes/WeaponTurret.tscn` | Турель | Позиция снаружи корпуса; у безоружных кораблей — убрать |
| `NetState` | `Node` + `net/NetState.cs` | Сеть | Копировать как есть |
| `Synchronizer` | `MultiplayerSynchronizer` | Репликация трансформов | `replication_config = scenes/ShipReplication.tres` |
| `ShipHealthState` + `ShipHealthSync` | `Node` + `.tres` | HP корабля | Копировать как есть (`ShipHealthReplication.tres`) |

### Интерактивные объекты — готовые сцены-«кирпичи»

Все интерактивные объекты вынесены в самостоятельные `.tscn` — их можно просто
инстансить (`instance=ExtResource(...)`) в любую сцену корабля/станции:

| Сцена | Состав | Подключение к носителю |
|---|---|---|
| `scenes/Seat.tscn` | `AttachPoint` Kind.Seat | любой предок с `NetState` (корабль) или `StationState` (станция) выше по дереву |
| `scenes/ControlPanel.tscn` | `Area3D`-панель + коллизия 0.45 м | проставить `SeatPath` на `Seat`-инстанс этого корабля |
| `scenes/Airlock.tscn` | каркас + 2 двери + `HatchPoint` (Kind.Hatch) | у переборки; у второго шлюза на том же теле сменить `NetId` точки (уникален в пределах носителя) |
| `scenes/Door.tscn` | одно полотно двери (слой Deck) | в любую палубу; `SlideDir`/`SlideDistance` — в инспекторе |
| `scenes/WeaponTurret.tscn` | турель с `Muzzle` | прямого ребёнка корабля зовут `Weapon` — код сдвигает её на нос при смене типа |
| `scenes/LandingPad.tscn` | площадка + точка крепления | уже инстансится в `Station.tscn`; работает в любом носителе |

Про слои: полные таблицы — `scripts/core/CollisionLayers.cs`
(1 Ship, 2 Station, 9 Deck/256, 10 ControlPanel/512; EVA-луч видит
панели+палубы+станцию+корпуса).

## 4. Порядок действий для нового корабля

1. Смоделировать GLB по п.1, положить в `assets/models/<тип>.glb`.
2. Дописать тип в `ShipTypes.cs`: enum + `ShipTypeSpec` (масса, Flight,
   `HullSize`, в `Accessories` можно null-массив если art-модель есть).
3. `scenes/<Тип>.tscn`: **продублировать `scenes/Ship.tscn`** (Save As), затем:
   - заменить инстанс модели в `ShipHull` на свой GLB и переименовать узел
     (`<TypModel>`); в `Ship.cs` добавить ветку показа своей модели по типу
     (по образцу `CourierModel`);
   - переставить `Seat`, `ControlPanel` в своё кресло/панель внутри КАЮТЫ;
   - перестроить `DeckInterior` и `CabinWalls` под свои габариты каюты:
     замкнутый объём со стеной по периметру, пол по уровню ног;
   - поставить `Airlock` в проём (габарит шлюза фиксированный, 1×1×2 м);
   - у `RigidBody3D` поменять `mass` на массу из каталога (код его всё равно
     перезапишет при смене типа, но тесты смотрят на консистентность);
   - удалить из копии всё, что осталось от чужой геометрии.
4. Спавн: если новый тип должен спавниться — точка/кнопка в дебаг-панели
   уже генерируется каталогом (`DebugRoot/.../Buttons`, «ShipType: ...»).

## 5. Чек-лист «интегрировалось свободно»

- Игрок снаружи → шлюз → внутренняя дверь → ходит по палубе в ботинках;
  стены не проходятся насквозь, потолок не отсекает голову.
- Из каюты наведение на панель (`F — сесть за штурвал`) работает; снаружи
  корабля панель перекрыта стеной — подсказки нет (так и должно быть).
- Посадка на станцию, стыковка, стрельба турели — без провалов картинки
  сквозь коллизию (картинка может «входить» в другие тела — физика по боксу).
- Полёт: тяга/инерция соответствуют каталогу, картинка не «отстаёт».

## 6. Типовые ошибки

| Симптом | Причина |
|---|---|
| Корабль при спавне закрутило / игрок не липнет к палубе | В сцене завёлся лишний инстанс `Player` — удалить |
| «F сесть» не появляется снаружи | Так и задумано: панель внутри каюты, вход через шлюз |
| Игрок проваливается сквозь пол каюты | `DeckInterior` не перестроен под новые габариты (или слой не 256) |
| Картинка больше/меньше физики | Модель не 1:1 с `HullSize`; не правьте масштаб в сцене |
| Нос корабля прицеливается назад | Модель в Blender смотрит носом на +Z — развернуть |
| Тесты Stage1/Stage7 упали после правки сцены | Изменены габариты/масса без правки каталога и тестов, или сдвинута панель/кресло |

## 7. Регресс после любой правки корабля

```
./run-tests.sh res://tests/Stage1Test.tscn   # каталог/типы/дебаг-панель
./run-tests.sh res://tests/Stage7Test.tscn   # EVA: hover/кресло/шлюзование
./run-tests.sh res://tests/HabDeckTest.tscn  # палубы/стены каюты
./run-tests.sh res://tests/AirlockTest.tscn  # шлюз полный цикл
```

Все четыре обязаны быть зелёными (3 падения «Flight из каталога» в Stage1 —
известный предсуществующий раскат каталога, ориентир: сверяйтесь с
`ShipTypes.cs`, а не с ожиданиями теста).
