# План: HUD в стиле X4: Foundations

> Составлен по результатам исследования интерфейса X4 (manual EGOSOFT недоступен из
> этой сети; структура восстановлена по HUD-гайдам Steam Community, обсуждениям
> forum.egosoft и разборами UI). Ниже — сначала «как устроено в X4», затем
> «как это ложится на наш проект», затем этапы реализации с критериями готовности.

## 1. Как устроен HUD в X4: Foundations

Экран пилота в X4 — это плоский 2D-оверлей (`CanvasLayer`) поверх 3D-вида, все
элементы полупрозрачные, тонкие линии, сине-белая гамма, шрифт моноширинный-техно.
Компоновка (экран 16:9, центр — прицел):

### 1.1 Центр экрана
- **Прицельная марка (crosshair)** — маленький крест/кольцо точно в центре; вокруг
  неё — **ars-of-locks / target ring**: когда цель захвачена, вокруг неё рисуется
  ломаная рамка-уголки + имя цели и дистанция под ней. Рамка следует за целью в
  проекции экрана; если цель за экраном — индикатор у края.
- **Наведение (targeting reticle)**: то, на что наведён курсор вcabine-режиме,
  подсвечивается имя/дистанцией.

### 1.2 Левый нижний угол — статус-бар корабля (главный блок X4)
Горизонтальная «капсула» из сегментов:
- **Силуэт корабля** (иконка класса) слева;
- **Hull** — полоса прочности (число + полоса, цвет: зелёный→жёлтый→красный);
- **Shield** — щит (пока не реализован в X4 для всех, но слот есть) — полоса;
- **Energy** — энергия (в X4 есть у крупных судов; у истребителей ограничена
  энергия сканирования/щита) — у нас будет аналог: энергия щита/двигателей;
- **Скорость**: текущая скорость м/с + максимальная, в X4 отображается в
  «псевдо-скоростном» блоке с цифрой;
- **Mode-иконки** мелким шрифтом: thrust/afterburner (boost), auto-roll,
  landing gear, airbrake — у нас это `boost`, `toggle_pilot_assist`,
  `toggle_pilot_camera` (chase/cockpit) — состояние «on/off» иконками.

### 1.3 Правый нижний угол — мини-карта (gravidar / local radar)
- Квадрат ~256×256, сверху — переключатель **Map** (секторная карта) /
  **Minimap** (локальный радар вокруг корабля);
- Локальный радар: центр — свой корабль; цели — цветные маркеры
  (по фракции: белый=нейтральный, синий=свой, красный=враг, жёлтый=торговец…),
  форма маркера — по классу (точка/треугольник/ромб/квадрат);
- **Ось высоты**: у каждого маркера короткая вертикальная черточка со сдвигом
  пропорционально ΔY относительно нашего корабля (в X4 гравидар показывает
  высоту «относительно курса»);
- Выбранная цель подсвечивается; подписи имён — опционально (T — показ/скрыть
  имена);
- Дистанция выбранной цели — цифрой под мини-картой.

### 1.4 Правый верхний угол
- **Целевой маркер / навигация**: строка «On: <цель> <дистанция>», ниже —
  текущаяPrimary mission/objective (у нас — строка задачи, например «Dock at
  Station X, 2400 м»);
- Слот **Commlink-лога** (в X4 справа всплывают сообщения комма) — у нас:
  короткий лог событий (урон, док, захват цели) на 5–7 строк, fade-out.

### 1.5 Левый верхний угол
- В X4 здесь минимально: индикатор крыльев/повреждений крыла (у X2/XT). Мы
  используем под **состояние мира**: тег режима (SERVER / CLIENT / OFFLINE),
  номер тика, пинг — переносим то, что сейчас живёт в DebugLayer/LblDebugInfo,
  но компактными 2 строками (детали остаются под F3).

### 1.6 Вертикальные шкалы по бокам прицела (в X4 — «speed bars»)
- Две вертикальные шкалы слева/справа от центра: составляющие скорости
  (латеральная/вертикальная) + маркер максимума. Упрощённый аналог: одна шкала
  продольной скорости по курсу + «скорость сближения» (approach speed).

### 1.7 Отображение целей в 3D (world-space markers)
- Над каждым кораблем/станцией X4 рисует в мире маленький **маркер-ромб с
  хвостом-выноской**: цвет по фракции, имя и дистанция по умолчанию скрыты
  (T включает). При наведении — «подсказка имени». Реализуется через
  `Label3D`/`Node3D`-оверлеи или через проектирование 3D→2D на HUD-слой.

### 1.8 Interaction mode (в X4 — по T/E)
В X4 вход в режим взаимодействия затемняет мир и показывает подписи над
объектами. У нас уже есть `toggle_interaction` — HUD-план оставляет слот:
подсветка интерактивных объектов рамкой + подпись действия («E — Dock»).

### 1.9 Чего в первой версии НЕ делаем
- Экономика, торговые маршруты, триммеры, миссии, логистика, вкладка «Storeroom»
  — вне объёма (в X4 это меню, не HUD).
- Секторная карта (Map) в полном смысле — только заглушка, поз. 3.6.

## 2. Что уже есть в проекте (на что опираемся)

| Потребность HUD | Готовый фундамент |
|---|---|
| HP корабля | `ShipHealthState.Hp/MaxHp`, реплицируется синхронизатором — есть у ВСЕХ копий кораблей, и у клиента тоже (Этап 4) |
| Позиция/поворот/скорость любого корабля | `NetState.NetPosition/NetRotation/NetLinearVelocity` + `Ship.ShipHull` (визуал) — на клиенте тоже актуальны |
| Идентификация/тип | `NetState.ShipNetId`, `ShipTypeValue`, `ShipTypeSpec.DisplayName` |
| Реестр всех кораблей на клиенте | `NetworkManager.Instance` + `RegisterShip/FindShip` — готовый источник для радарa |
| Скорость/boost/assist | `FlightModel.MaxLinearSpeed`, экспорт `boost`, `toggle_pilot_assist` (флаг `NetState.PilotAssist`) |
| Ближайшая цель | сцена `Target.tscn` + `TargetState` |
| Слой UI | образец `DebugLayer.cs` (CanvasLayer + .tscn + DebugInfoBus) — берём структуру, не смешиваем с дебагом |
| Пространственный запрос | `SpatialIndex` (чистый, без Godot) — серверная AOI, переиспользуема клиентом для «кто рядом» |

Чего НЕТ и надо завести (минимально):
- **Фракции/отношения** — в X4 весь цвет HUD от них зависит. Минимум:
  `enum Faction { Neutral, Player, Hostile }` + поле `FactionValue` в `NetState`
  (byte, репликуется как остальные), палитра цветов маркеров. Это одна строка
  сетапа и уже даёт «x4-вид».
- **Цель игрока (target)** — выбор цели пилотом (клик/LMB-lock или Tab cycle).
  Пока есть только физический `Target`-мишень; вводим `PilotTarget` — NetId
  выбранной цели на стороне игрока (локально, не реплицируется).
- **Энергия щита** — заглушка: поле `Shield/MaxShield` в `ShipHealthState`
  (пока 0/0 или регенерируемый буфер — решение на этапе 6 ниже).

## 3. Этапы реализации

### Этап H1 — каркас HUD-слоя (без данных)
- `scenes/HudLayer.tscn` + `scripts/ui/HudLayer.cs : CanvasLayer`
  (layer выше DebugLayer; `ProcessMode = Always` не нужен — HUD живёт на паузе
  только если задумано, по умолчанию Normal).
- Слоты-заглушки: `Center/Crosshair`, `BottomLeft/StatusPanel`,
  `BottomRight/RadarPanel`, `TopLeft/WorldTag`, `TopRight/ObjectivePanel`.
- Input-map: `hud_toggle` (например H) — полностью спрятать HUD (в X4 это
  настройка, у нас — хоткей).
- **Критерий:** на экране пустой каркас с полупрозрачными плейсхолдерами;
  H прячет/показывает; DebugLayer (F3) не конфликтует.

### Этап H2 — статус-бар своего корабля
- Источник: локальный Ship игрока (`Player.GetMountedShip()` — добавить
  геттер, если нет; данные: `ShipHealthState`, `FlightModel`, `NetState`).
- Содержимое панели (слева направо): иконка класса (`ShipTypeSpec.DisplayName`
  первая буква/глиф), **Hp/MaxHp** полоса с числом и цветом
  (>60 % зелёный, 30–60 жёлтый, <30 красный), **Shield** (пока серая заглушка
  0/0), **скорость** `NetLinearVelocity.Length():F0` м/с + `MaxLinearSpeed`
  серым, режимные иконки: `boost` (удерживается ли), `assist on/off`
  (`NetState.PilotAssist`), `camera chase/cockpit` (из `Player`).
- Все числа — только из реплицированных состояний, никаких обращений к нодам
  чужих кораблей мимо `NetworkManager.FindShip`.
- **Критерий:** п. проверки: у клиента-наблюдателя статус-бар своего корабля
  совпадает с серверным через 1–2 с после урона (HP уже реплицируется —
  тест из Этапа 4 подтверждает трассу).

### Этап H3 — цели в 3D (world markers) + выбор цели
- `TargetingService` (`scripts/ui/TargetingService.cs`): локально на клиенте;
  Tab — цикл по кораблям из реестра `NetworkManager` (сортировка по углу к
  курсу камеры, затем по дистанции); LMB при наведении — выбрать цель под
  курсором (raycast по коллайдерам кораблей, уже есть в `Ship.cs` через
  мышь-пик из проб `ProbeMousePick`).
- Маркер цели на HUD: рамка-уголки вокруг проекции цели
  (`Camera3D.UnprojectPosition` / `WorldMatrix * ToVector4` → `to_screen`),
  имя `DisplayName` + дистанция; если цель за камерой — маркер у края экрана
  (кламп).
- Мир-маркеры: `Label3D` с ромбом над каждым кораблём: цвет по фракции,
  текст «Имя \n N m» скрыт по умолчанию, хоткей `T`-подобный (`hud_labels`)
  включает. Пока без фракций — все белые.
- **Критерий:** Tab переключает цель, рамка следует за целью при повороте
  камеры; цель за спиной — маркер у края; дистанция обновляется.

### Этап H4 — фракции и цвета (мини)
- `enum FactionValue : byte { Neutral = 0, Player = 1, Hostile = 2 }`;
  `[Export] public byte FactionValue` в `NetState` (реплика идёт бесплатно,
  батч-запись Record его не включает — метрика rec/s не растёт, как с HP);
- сервер задаёт при спавне: станция/свои = Player, `Target` = Hostile,
  прочие = Neutral;
- палитра: Player #6fa8ff, Neutral #d8d8d8, Hostile #ff5a4a — одна таблица
  `FactionColors` в `scripts/ui/HudTheme.cs`, от неё зависят маркеры H3,
  цель H3 и радар H5.
- **Критерий:** на клиенте цвет маркера врага красный — значит byte-поле
  доехало репликой (headless-тест по образцу п.27 из bugs-протоколов).

### Этап H5 — локальный радар (см. radar-plan.md, этап R1–R3)
- Панель BottomRight заполняется виджетом `RadarPanel` из radar-плана.
- **Критерий:** тот, что у radar-плана R3.

### Этап H6 — верхние углы: тег мира, objective, комм-лог
- TopLeft: 2 строки — режим (`OFFLINE`/`SERVER`/`CLIENT` из `NetworkManager`)
  и FPS/пинг (пинг уже считается в `NetworkManager`, вынести в свойство);
- TopRight: строка «On: {target} — {dist}» из `TargetingService`; ниже —
  `CommlinkLog` (VBox из 6 Label, события: урон, dock, захват/потеря цели;
  источник — шина `HudEventBus` по образцу `DebugInfoBus`, подписки в
  `Ship/Docking` точечные: один вызов `HudEventBus.Report(...)` на событие);
- **Критерий:** после докинг-события строка «Docked at Station — 0 m»
  появилась в логе и померкла через 8 с.

### Этап H7 — энергия/щит (по желанию, отдельным слотом)
- Если решаем делать: `Shield/MaxShield` в `ShipHealthState` + реген на
  сервере (тик интегрирует), урон сначала снимает щит; HUD H2 уже готов к
  этому слоту.
- **Критерий:** урон 20 при щите 50 → Hp не меняется, щит 30; на клиенте
  обе полосы совпадают.

## 4. Правила реализации (в стиле проекта)
- UI-дерево — в .tscn, код только связывает и обновляет (как DebugLayer).
- Никаких прямых мутаций чужих состояний с клиента: HUD только читает
  `ShipHealthState/NetState` — вся правда идёт репликой.
- Каждый этап — зелёный прогон `run-tests.sh` + ручной запуск сцены;
  новые проверки — в `tests/Stage6Test.*` по образцу Stage5.
- Шрифт/палитра — один `HudTheme` (StyleBoxFlat полупрозрачный
  #10161ecc, рамка #4a6a8a), чтобы вид был «x4», а не дефолтный Godot.

## 5. Риски
- Проецирование цели на экран при `far = 4000` — цель далеко: держать
  минимальный размер рамки и кламп к краям.
- Tab-цикл по всему реестру при 100+ кораблях — сортировку считать раз в
  0.2 с, не каждый кадр (по образцу `SpatialIndex.Rebuild` 4 Гц).
- Не смешивать DebugLayer и HUD: разные CanvasLayer, разные хоткеи.
